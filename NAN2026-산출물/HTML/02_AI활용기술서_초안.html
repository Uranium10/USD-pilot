U.S.D AI 활용 기술 문서

1. 활용 목적

U.S.D의 AI 활용 목표는 가격을 임의로 결정하게 하는 것이 아니라, 여러 주차에 걸쳐 이어지는 시장 사건과 뉴스·소문의 맥락을 매 플레이마다 새롭게 구성하는 데 있다. 금융 판정과 핵심 수치는 코드가 담당하고 AI는 서사적 원인과 표현을 담당한다. 이를 통해 생성 결과의 다양성을 확보하면서도 게임 규칙의 재현성과 공정성을 유지한다.

AI는 두 영역에서 구분하여 활용했다.

  1. 게임 런타임 AI: 전체 서사 계획과 주간 시장 사건 생성
  2. 개발 보조 AI: 기획 검토, 코드 구현·리뷰, 테스트 설계, 문서 초안 작성

두 영역을 구분함으로써 플레이어가 경험하는 생성 기능과 개발 과정의 생산성 도구를 혼동하지 않도록 했다.

2. 런타임 생성 구조

2.1 RunPlan: 7주 전체 서사 골격

RunPlan은 1~7주차에 걸친 주요 사건 아크, 예고 시작 시점, 사건 확정 시점과 관련 종목 슬롯을 정의한다. Claude Opus 5 high를 사용해 품질 우선으로 생성하며, 실제 플레이 시작 시 즉시 생성하지 않고 사전에 검증된 RunPlan 풀을 Turso에 저장해 무작위로 선택한다.

이 방식은 다음 효과가 있다.

  • 플레이 시작 시 장시간 대기 제거
  • 한 번 검증한 서사 골격을 안전하게 재사용
  • 모델 장애 시에도 기존 풀을 활용
  • 런 전체에서 사건의 예고와 결말 시점을 일관되게 유지

RunPlan은 실제 기업명이 아닌 stock-1~stock-5 슬롯을 사용한다. 따라서 같은 골격도 매 게임 선택되는 기업 조합과 결합해 다른 맥락을 형성한다.

2.2 CycleScenario: 주간 사건 상세화

각 주차 시작 시 GPT-5.6 Terra가 현재 주차에 해당하는 RunPlan 아크와 이전 주의 세계 상태를 입력받아 7일치 사건과 소문을 생성한다. 결과는 strict JSON Schema로 제한하며 다음 항목을 중심으로 출력한다.

  • 사건 ID와 대상 종목
  • 상승·하락 방향 및 영향 규모
  • 장중 사건 발생 시점
  • 플레이어에게 노출되는 뉴스 헤드라인
  • 사건을 예고하는 소문의 출처·신뢰도 등급·문장
  • 다음 주로 전달할 미해결 상태
  • RunPlan 정합성 자체 점검 결과

실제 게임이 사용하지 않는 중복 설명 필드는 기본 스키마에서 제거했다. 필요할 경우 서버 환경변수 AI_CYCLE_SCHEMA_MODE=verbose로 기존 전체 스키마와 프롬프트를 즉시 복구할 수 있다.

2.3 결정론적 시장 컴파일

AI 응답은 곧바로 가격이 되지 않는다. 게임 코드가 seed를 이용해 기본 가격 경로를 생성하고, 검증된 AI 사건을 지정된 종목·방향·시점에 컴파일한다. 정확한 가격, 변동 상한, 정보 가격, 소문 판정, 부채와 채굴 수치는 모두 코드에 의해 계산된다.

이를 다음과 같이 정리할 수 있다.

사전 생성 RunPlan → 주간 CycleScenario → JSON Schema 검증 → 결정론적 가격 경로에 사건 컴파일 → 플레이

이 구조는 생성형 AI의 장점인 맥락과 다양성을 활용하면서, 수치 오류가 게임 경제를 직접 훼손하는 위험을 줄인다.

3. 안정성 및 비용 제어

Filler짧은 문장 보조 실험Gemini Flash 계열 실험 경로, 현재 정식 시장 경로에는 미연결

고가 모델은 런 전체에서 가장 중요한 구조 설계에 제한적으로 사용하고, 반복 호출되는 주간 단계는 비용과 품질의 균형이 좋은 모델을 사용한다. 날짜별 문구를 별도 모델로 병렬 생성하는 실험도 수행했으나 실측상 비용 증가와 재시도 지연이 확인되어 정식 경로에 적용하지 않았다.

3.2 출력 슬림화 실험

동일 RunPlan과 동일 주차를 기준으로 GPT-5.6 Terra medium을 비교했다.

구분평균 시간평균 비용평균 출력 토큰자동 검사
기존 전체 출력35.2초약 $0.05913,673평균 75점
실제 사용 필드 중심 출력19.8초약 $0.03311,9712회 모두 100점

소규모 표본이므로 절대 성능을 단정하지는 않지만, 해당 실험에서는 시간 43.6%, 비용 43.9%, 출력 토큰 46.3%가 감소했다. 입력 프롬프트는 반복 호출 시 2,926토큰 중 2,923토큰이 자동 캐시에 적중했으며, 주요 병목이 입력보다 구조화 출력에 있음을 확인했다.

3.3 반복 재시작 보호

동일 사용자가 새 게임을 무한 반복해 1주차 GPT를 계속 호출하는 것을 막기 위해 기기별 보호 캐시를 적용했다.

  • 동일 기기의 30분 이내 재시작은 직전 1주차 시장 전체 재사용
  • 24시간당 신규 1주차 생성 최대 3회
  • 시장과 함께 RunPlan·다음 세계 상태를 복원해 서사 연속성 유지
  • 다른 사용자와 결과를 공유하지 않고 해당 기기에만 적용

이를 통해 정상적인 새 플레이의 생성 다양성은 유지하면서 반복 재시작에 의한 토큰 낭비와 리세마라를 제한한다.

3.4 장애 대응

  • API 키는 Vercel 서버 함수에서만 사용하며 클라이언트 번들에 포함하지 않는다.
  • AI 상태와 게임 저장 상태를 Turso의 별도 테이블로 관리한다.
  • 동일 기기·주차의 중복 요청은 진행 중 요청 캐시로 합류시킨다.
  • AI 또는 네트워크 실패 시 결정론적 로컬 시장으로 자동 전환한다.
  • 응답은 JSON Schema와 애플리케이션 검증을 모두 통과해야 컴파일한다.
  • 7주차 고정 대폭락과 핵심 엔딩 조건은 AI가 덮어쓰지 못하도록 코드가 보존한다.

4. 개발 과정의 AI 활용

개발 과정에서는 Claude, Codex, Gemini 계열 도구를 다음과 같은 보조 업무에 활용했다.

  • 요구사항과 설계 문서의 상호 검토
  • React 컴포넌트 및 서버 함수 구현 보조
  • 상태 저장, 시장 생성, 비용 측정 코드 리뷰
  • 밸런스 수식 및 엣지 케이스 검토
  • 자동 테스트와 회귀 테스트 작성
  • UI 문구, 임시 스토리, 제출 문서 초안 생성

AI가 제안한 결과는 그대로 채택하지 않고 실제 빌드, 린트, 상태 머신 검사, DB 통합 검사와 플레이 피드백을 통해 수정했다. 예를 들어 병렬 생성 방식은 이론상 속도 개선이 예상되었으나 실제 측정에서 비용과 시간이 증가해 정식 경로에서 제외했다.

5. 사람의 역할과 검수 원칙

  • 게임 규칙, 세계관 방향, 재미의 기준과 최종 채택 여부는 개발자가 결정한다.
  • 생성 모델은 가격 수치와 승패 판정을 직접 결정하지 않는다.
  • 모델 출력은 구조 검증과 코드 기반 제한을 통과해야 한다.
  • 실험 결과가 좋지 않으면 적용하지 않고 기존 경로를 유지한다.
  • 모델명·비용·속도는 가능한 경우 실제 호출 결과를 기록한다.
  • 이미지·음원·폰트 등 외부 자산의 사용 권한은 최종 제출 전에 별도 확인한다.

6. 향후 개선 방향

  1. 운영 환경에서 주간 생성 표본을 누적해 품질·비용·시간의 신뢰구간 확보
  2. RunPlan별 주간 시나리오 사전 생성 또는 다음 주 백그라운드 선생성 검토
  3. 생성 뉴스의 중복 표현과 존재하지 않는 기업 언급에 대한 자동 평가 강화
  4. 플레이어 행동을 과도하게 추적하지 않는 범위에서 생성 다양성 분석
  5. AI 미사용 결정론적 모드와 AI 결합 모드의 플레이 만족도 비교
