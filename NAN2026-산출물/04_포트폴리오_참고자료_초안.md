부모에게 상속된 거액의 빚을 갚기 위해, 8분의 시장과 끝나지 않는 밤을 반복하며 정보·노동·투자를 선택하는 채무 생존형 트레이딩 로그라이크.

## 4. 기술 구조 요약

### 클라이언트

React 컴포넌트가 타이틀, 방, 정보 거래소, 시장 터미널, 야간 활동과 스토리 오버레이를 구성한다. 낮 시간 진행은 React 렌더링과 분리된 스테이지 엔진이 담당하며, Zustand가 시장·거래·인벤토리·스토리 상태를 중앙 관리한다. 차트는 Canvas로 렌더링해 장중 갱신과 커서 상호작용을 처리한다.

### 서버와 저장

Vercel Functions가 시장 생성과 세션 저장 API를 제공한다. Turso에는 게임 진행 세션, 보유 종목, AI 런 상태, RunPlan 풀과 재시작 보호 캐시가 분리 저장된다. 로컬 개발에서는 Vite 미들웨어가 동일 API 인터페이스를 제공한다.

### AI 시장

사전 생성된 RunPlan이 7주 서사 골격을 제공하고 GPT 주간 모델이 현재 주차 사건을 구조화 출력으로 생성한다. 코드가 seed 기반 가격 경로에 사건을 컴파일한다. AI 장애 시 로컬 생성기로 전환한다.

## 5. 개발 과정에서 해결한 주요 문제

### 배포·로컬 실행 경로 분리

초기에는 로컬 실행에도 Vercel 인증이 개입해 개발 서버가 곧바로 종료되는 문제가 있었다. 로컬에서는 Vite 미들웨어, 배포에서는 Vercel Function을 사용하도록 인터페이스를 통일해 인증 없이 `localhost:5173`에서 실행할 수 있게 했다.

### 저장 정합성

주차와 일차가 1로 돌아가는 문제를 해결하기 위해 세션 revision, 서버 응답 검증, 브라우저 백업과 Turso 저장을 함께 사용했다. 시장 데이터와 AI 세계 상태가 서로 덮어쓰지 않도록 저장 테이블도 분리했다.

### 생성 비용과 대기시간

RunPlan을 사전 생성 풀로 전환하고, 주간 GPT의 출력 스키마에서 런타임 미사용 필드를 제거했다. 소규모 동일 조건 실험에서 주간 호출 평균 시간이 35.2초에서 19.8초, 비용이 $0.0591에서 $0.0331로 감소했다. 반복 재시작에는 기기별 보호 캐시를 적용했다.

### 생성형 AI의 통제 범위

AI가 실제 가격을 직접 정하게 하지 않고 사건의 원인·방향·표현만 생성하도록 제한했다. 가격 상한, 부채, 소문 판정과 7주차 핵심 사건은 코드가 보장한다. 실험적 병렬 생성이 예상과 달리 느리고 비쌌던 사례는 정식 경로에서 제외했다.
