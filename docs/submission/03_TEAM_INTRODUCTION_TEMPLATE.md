## 5. 협업 방식

### 의사결정

[입력 필요: 실제 사용한 방식을 선택해 서술]

- 게임의 애매한 결정은 "짧은 시간에 핵심 재미가 전달되는가"를 기준으로 판단했다.
- AI 기능은 품질뿐 아니라 호출비와 플레이 대기시간을 실측한 뒤 채택했다.
- 새 실험은 기존 운영 경로와 분리하고, 결과가 나쁠 경우 연결하지 않았다.
- 설계 문서와 실제 코드가 다르면 현재 동작하는 코드와 검증 결과를 우선했다.

### 기록

- 연속 작업 로그: `log.txt`
- 게임 설계: `USD_SPEC.md`, `STORY.md`
- AI 설계·실험: `agent_workthrough_*.md`, 벤치마크 스크립트
- 코드 변경: [입력 필요: Git 브랜치/PR/커밋 규칙]
- 일정·이슈 관리: [입력 필요: 사용 도구]

### 품질 관리

- 정적 검사: `npm run lint`
- 프로덕션 빌드: `npm run build`
- 스토리/엔딩/AI 연결 검사: `npm run check:story-systems`
- 코인·채굴 밸런스 검사: `npm run check:coin`
- 세션 저장과 재시작 보호 검사
- 실제 LLM 호출을 통한 비용·시간·문장 품질 비교

## 6. 주요 문제와 해결

아래 사례 중 팀이 실제로 주도한 내용을 선택하고 담당자를 표시한다.

### 문제 1. AI 생성 대기 때문에 실시간 템포가 끊김

- 문제: 주간 시나리오 생성에 약 15~25초가 필요했다.
- 해결: AI 시나리오와 결정론적 가격 시장을 분리하고, 다음 주 시나리오를 현재 주 시작 시 미리 생성했다.
- 결과: 프리페치 약 19.5초 후 실제 주차 도달 응답 약 0.1초.
- 담당: [입력 필요]

### 문제 2. 세션 간 AI 서사가 섞일 위험

- 문제: 서버리스 모듈 전역 캐시는 콜드 스타트 때 사라지고 웜 인스턴스에서 여러 사용자가 공유할 수 있었다.
- 해결: RunPlan과 worldState를 `deviceId`별로 Turso에 저장하고 주차별 입력 상태를 분리했다.
- 결과: 재시작과 요청 순서 변화에도 한 세션의 서사가 유지된다.
- 담당: [입력 필요]

### 문제 3. AI 문장이 정상이어도 UI에서 훼손됨

- 문제: 뉴스 본문의 첫 쉼표 앞 내용을 무조건 제거해 주어나 출처 절이 사라졌다.
- 해결: 실제 종목명 접두사인 경우에만 제거하도록 뉴스 텍스트 로직을 분리했다.
- 결과: AI 원문 보존과 로컬 뉴스 하위 호환을 함께 확보했다.
- 담당: [입력 필요]

### 문제 4. 비용과 품질의 균형

- 문제: 강한 주간 모델은 판당 비용과 생성시간이 높았다.
- 해결: 불필요한 스키마 필드를 제거하고 Terra, Luna, Gemini 계열을 같은 RunPlan으로 실측했다.
- 결과: Luna low로 전환해 Terra medium 대비 비용 58.0%, 시간 30.6% 감소하면서 14/14 검증을 통과했다.
- 담당: [입력 필요]
